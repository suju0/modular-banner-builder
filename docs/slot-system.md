# 슬롯 시스템 설계

## 핵심 개념

"수백 가지 배너를 어떻게 대응할 것인가"에 대한 답:
**레이아웃(수직 구성+프레임) × 배치/정렬 × 모듈(콘텐츠) × 컬러 × 배경 이미지** 분리

레이아웃과 사이즈는 **웹 / 앱 채널로 분류**한다. 앱 지면(모달 팝업·홈 캐러셀·하단 시트)은
비율과 프레임 형태가 웹과 완전히 달라 섞어 두면 잘못 고르기 쉽다.

```
┌────────────────────────────────────────────────┐
│                Banner Output                   │
├────────────────────────────────────────────────┤
│  Layout    → 수직 구성(y) + 프레임 형태          │
│  배치/정렬 → 블록의 수평 위치 + 글줄 맞춤        │
│  Module    → 각 슬롯에 들어갈 블록              │
│  Color     → 역할 8개 오버라이드                 │
│  Image     → 배경 합성 (변형·확장 + 그라데이션)  │
└────────────────────────────────────────────────┘
```

## v0.3~v0.4 에서 정리한 것

### 1. 이미지 슬롯 제거
v0.2 까지 레이아웃은 "이미지를 어디에 놓을지"까지 정의했다
(좌측텍스트+우측이미지 / 클린 프로덕트 / 콜라보…). 문제는 두 가지였다.

- 실제 이커머스 배너에서 상품컷은 텍스트 옆 네모난 슬롯에 들어가지 않는다.
  **배경에 합성**되고, 텍스트는 그 위에 얹힌다.
- 이미지 슬롯이 있는 레이아웃 / 없는 레이아웃이 갈려서, 이미지를 올린 뒤
  "이 레이아웃에는 이미지 슬롯이 없습니다" 같은 안내를 해야 했다.

이제 `imageArea` 모듈과 슬롯은 없다. 이미지는 **어떤 레이아웃에서든 배경**이며,
구도는 Crop 으로 잡고 텍스트 가독성은 그라데이션으로 확보한다.

### 2. 레이아웃은 수직 구성만 정의
```javascript
{
  id: "wide-editorial",
  block: { w: "46%", position: "center", align: "left" },  // 기본값
  slots: {
    eventTag: { y: "26%" },
    title:    { y: "36%" },
    subtitle: { y: "60%" },
    discount: { y: "74%" },
    date:     { y: "88%" },
  },
}
```
- 수평 좌표(x)와 정렬은 레이아웃이 정하지 않는다 → 사용자 설정
- `block.w` 는 **모든 모듈이 공유하는 블록 폭**이다. 폭이 같아야 태그·타이틀·서브카피·기간의
  정렬선이 하나로 맞는다 (레퍼런스 배너의 좌측 정렬 구성이 이 구조다)
- `block.position/align` 은 그 템플릿에 어울리는 기본값이며, 템플릿을 고르면 함께 적용된다

### 3. 프레임 형태와 프레임 요소 (v0.4)
앱 지면은 텍스트 구성만으로 재현되지 않는다. 지면 자체의 형태가 디자인의 일부다.

- `frame.radius`: `none` | `top`(하단 시트) | `all`(모달 팝업) → `getFrameRadius()`
  PNG 로 내보내면 라운드 코너가 투명하게 저장된다
- `cta`: `{ style: "bar" }` 하단 풀와이드 바(모달) / `{ style: "button" }` 인라인 버튼(시트)
- `indicator`: `"bottom"` 캐러셀 인디케이터 — **미리보기 전용**. 캐러셀이 있는 지면은
  앱 홈 메인 배너뿐이라 `app-hero` 에만 붙는다. 다른 템플릿은 이 키가 없고 토글도 비활성.

**CTA 바는 슬롯이 아니다.** 지면 전체 폭을 쓰므로 `BannerRenderer` 의 프레임
레이어에서 그린다. (인라인 CTA 버튼만 슬롯 — 텍스트 블록과 정렬선을 공유해야 한다)

**캐러셀 인디케이터는 배너 이미지에 굽지 않는다.** 그건 앱이 그리는 지면 UI 라
에셋에 들어가면 안 된다. 다만 위치를 보면서 구도를 잡아야 하므로 미리보기에서만
표시하고(캔버스 툴바 토글), Export 경로에는 플래그를 넘기지 않는다.

배경 장식 도형(원형 등)은 v0.4 에서 제거했다. 이미지를 넣지 않았는데도 원형이
깔려 보이는 문제가 있었고, 실제 컬리 배너는 사진과 그라데이션으로 배경을 만든다.

### 4. 배치(position) × 정렬(align) 분리
컬리 PC 풀배너는 **블록은 화면 중앙, 글줄은 좌측 정렬**이다. 이 조합을 표현하려면
두 축을 분리해야 한다.

```javascript
resolveSlotBox(layout, moduleId, { position, align })
// position: left   → left: 7%,   transform: none
//           center → left: 50%,  transform: translateX(-50%)
//           right  → left: 93%,  transform: translateX(-100%)
// align:    글줄 맞춤 (text-align)
```
3 × 3 = 9 가지 조합을 모든 템플릿에서 쓸 수 있다.

### 조합 수 계산
- 레이아웃 8종(웹5/앱3) × 배치 3 × 정렬 3 × 두께 3단 × 모듈 조합(2^7=128)
  = **27,648가지** 구조 변형
- 여기에 8개 역할 컬러 오버라이드, 배경 이미지 + 변형 + 확장 + 그라데이션이 곱해지면
  사실상 무한

## 표준 타이포 · 위치 — Figma 원본 기준

앱 홈 메인 배너(1125×840) Figma 파일이 표준이다. 다른 템플릿의 값도 이 스케일에서 파생한다.

| 요소 | 크기 | 두께 | 자간 |
| --- | --- | --- | --- |
| 컬리와 함께하는 (titleLead) | 86px | Regular 400 | -5% |
| 9월의 결제 혜택 (title) | 86px | Medium 500 | -5% |
| 케이뱅크 이용하고… (subtitle) | 42px | Regular 400 | +3% |
| 09.01 - 09.30 (date) | 38px | Regular 400 | 0% |

```
기준값 = min(높이, 너비 × 0.55)      // 1125×840 → 618.75
TYPE_RATIO   = { title 0.139, subtitle 0.0679, date 0.0614, ... }   // 86/618.75 등
LETTER_SPACING = { title -0.05, subtitle 0.03, date 0 }             // em
LINE_HEIGHT  = { title 1.17, subtitle 1.24 }                        // 실측 행간에서 역산
```

행간은 Figma 의 잉크 간격에서 역산했다 — 타이틀 두 줄의 잉크 상단 간격 100.4px ÷ 86px = 1.17,
서브카피 52px ÷ 42px = 1.24.

### 잉크 좌표 → 라인박스 좌표 변환 (중요)
Figma 의 y 는 **글자 잉크 상단**이고 CSS `top` 은 **라인박스 상단**이다. 그대로 옮기면
글자가 아래로 내려간다. 변환식:

```
라인박스 top = 잉크 top − ( (line-height − font-size)/2 + (폰트 어센트 − 잉크 어센트) )
```

어센트 값은 canvas `measureText()` 의 `fontBoundingBoxAscent` / `actualBoundingBoxAscent`
로 실측한다(레이아웃에 의존하지 않아 신뢰할 수 있다). 86px Pretendard 는 보정값 ≈ 20px.

그렇게 역산해 넣은 app-hero 슬롯: 타이틀 8.8% · 서브카피 37% · 기간 87.6%.
Export 결과 잉크 위치를 다시 재서 검증했다 — Figma 89.5/189.9/321.9/373.9/749.8 대비
실제 89/191/321/373/749 (오차 1px 이내).

### 캐러셀 인디케이터 (미리보기 전용)
Figma 좌표를 비율로 환산해 `INDICATOR_SPEC` 에 넣었다.

```
알약    322 × 84 @ (767, 720)   → 높이 84/840, 폭 = 높이 × 3.833, 우측 36/1125, 하단 36/840
재생 원  84 × 84 @ (671, 720)   → 알약 왼쪽 12px (= 높이 × 0.143)
내부 텍스트 40px (= 높이 × 0.476)
```

**배너 이미지에는 절대 들어가지 않는다.** 앱이 그리는 지면 UI 이므로
미리보기 오버레이로만 렌더하고(`PreviewIndicator`, `data-export-ignore`),
Export 경로에는 플래그를 넘기지 않는다. 캔버스 툴바의 "인디케이터 표시" 로 껐다 켤 수 있다.
Export 결과의 인디케이터 자리 픽셀이 배경색과 동일한 것으로 검증했다.

## 배치 · 정렬 (Figma Design 패널 방식)

사이드바의 "텍스트 배치 · 스타일"은 Figma 의 Design 패널을 따른다.

| UI | 성격 | 하는 일 |
| --- | --- | --- |
| 정렬 아이콘 6개 | **동작** (누르면 옮긴다) | 좌/가로중앙/우 · 상/세로중앙/하 |
| 위치 X · Y | 값 | 배너 좌상단 기준 px. 직접 입력 / ↑↓ (Shift 10px) |
| 글줄 정렬 | 모드 | 박스 안에서의 글줄 맞춤 (`block.align`) |

대상은 **위치 편집 모드에서 고른 슬롯 하나**, 고르지 않았으면 **텍스트 블록 전체**다.

### 좌표는 계산이 아니라 실측이다

폰트·자간·줄바꿈이 반영된 실제 박스는 값으로 추정할 수 없다. 그래서
`lib/slotGeometry.js` 가 미리보기 DOM(`[data-preview-banner]` 안의
`[data-slot-id]`)을 `getBoundingClientRect` 로 재고, 미리보기 배율을 나눠
배너 좌표(px)로 환산한다. Export 는 화면 밖에 별도 트리를 만들기 때문에
반드시 미리보기 루트 안에서만 찾는다.

여기서 두 가지가 따라온다.

1. **슬롯에 위치 트랜지션을 두지 않는다.** 애니메이션이 도는 동안
   `getBoundingClientRect` 는 보간된 중간 좌표를 돌려주고, 그 값으로 정렬을
   계산하면 엉뚱한 곳에 붙는다 (실제로 좌측 정렬이 960px 로 계산된 적이 있다).
2. **정렬 계산은 표시용 state 가 아니라 클릭 시점의 실측을 쓴다.** 연속으로
   누를 때 한 박자 늦은 값으로 계산하면 어긋난다.

### 블록 전체의 가로 정렬만 예외

오프셋이 아니라 레이아웃 앵커(`textPosition`)를 바꾸고 `dx` 를 0 으로 비운다.
그래야 규격을 바꿔도 정렬이 유지되고, "위치 초기화" 가 깔끔한 상태로 남는다.

## 규격 ↔ 템플릿 짝

앱 지면 규격은 "형태"가 곧 스펙이다. 그래서 규격을 고르면 그 규격을 권장하는
템플릿까지 함께 적용한다 (`handleSizeSelect`).

| 규격 | 짝이 되는 템플릿 |
| --- | --- |
| 앱 모달 팝업 1080×1240 | 앱 모달 팝업 |
| 앱 홈 메인 1125×840 | 앱 홈 메인 배너 |
| 앱 하단 시트 1125×880 | 앱 하단 시트 팝업 |
| PC 풀배너 1920×360 | 와이드 에디토리얼 |
| 앱 카테고리 · 앱 푸시 · PC 히어로 · SNS 정사각 | 없음 — 지금 템플릿 유지 |

짝이 없는 규격에서는 비율 경고(SizeSelector)만 띄운다. 자동으로 바꿀 대상이
없으니 사용자가 템플릿을 고르거나 위치를 조정하는 게 맞다.

### 인디케이터는 "템플릿 + 규격"이 모두 맞을 때만

`indicatorAvailable = layout.indicator && selectedSize.id === layout.recommendedSize`

앱 홈 메인 배너 템플릿을 720×240 같은 다른 규격으로 쓰면 인디케이터 좌표가
실제 지면과 어긋난다. 그래서 토글 버튼을 숨기고, 미리보기에도 그리지 않는다
(`showIndicator && indicatorAvailable`).
